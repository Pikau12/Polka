# Polka API

Документация текущих маршрутов backend. Обновлено: 21 ноября 2026 года.

## Общие правила

Базовый URL для локального запуска: `http://localhost:8080/api`.

Запросы с телом передают JSON:

```http
Content-Type: application/json
```

Все маршруты игр, коллекции и сессий требуют access token:

```http
Authorization: Bearer <access_token>
```

Маршруты `/api/auth/*` доступны без access token. Для обновления токенов и выхода refresh token передаётся в теле запроса.

Текущие `GET /api/games/search` и `GET /api/games` читают JSON из тела запроса. Фильтры и идентификаторы для этих маршрутов не читаются из query-параметров. В Postman используй Body → raw → JSON.

Идентификатор текущего пользователя определяется по access token. Время в ответах авторизации передаётся в Unix-секундах, даты сессий — строками RFC3339.

## Авторизация

### `POST /api/auth/register`

Создаёт пользователя. Все четыре поля обязательны; `email` должен иметь корректный формат.

Запрос:

```json
{
  "login": "user",
  "password": "password",
  "email": "user@example.com",
  "username": "User"
}
```

Ответ: `201 Created`, без тела. Для получения токенов нужен отдельный вход.

Ошибки: `400` — неверное тело запроса; `409` — пользователь с таким логином или email уже существует; `500` — внутренняя ошибка.

### `POST /api/auth/login`

Запрос:

```json
{
  "login": "user",
  "password": "password"
}
```

Ответ `200 OK`:

```json
{
  "access_token": "...",
  "token_type": "Bearer",
  "refresh_token": "...",
  "access_expires_at": 1795219200,
  "refresh_expires_at": 1797807600
}
```

`access_expires_at` и `refresh_expires_at` — время истечения соответствующих токенов в Unix-секундах.

Ошибки: `400` — неверное тело; `401` — неверный логин или пароль; `500` — внутренняя ошибка.

### `POST /api/auth/refresh`

Запрос:

```json
{
  "refresh_token": "..."
}
```

Ответ `200 OK`:

```json
{
  "access_token": "...",
  "refresh_token": "...",
  "token_type": "Bearer",
  "expires_at": 1795219200
}
```

`expires_at` относится к новому access token. Старый refresh token отзывается; клиент должен сохранить новый refresh token из ответа.

Ошибки: `400` — неверное тело; `401` — refresh token не найден, отозван или истёк; `500` — внутренняя ошибка.

### `POST /api/auth/logout`

Запрос:

```json
{
  "refresh_token": "..."
}
```

Ответ `200 OK`:

```json
{
  "message": "logged out successfully"
}
```

Отзывает переданный refresh token. Уже выданный access token остаётся действительным до своего истечения.

Ошибки: `400` — неверное тело; `401` — refresh token не найден или уже отозван; `500` — внутренняя ошибка.

## Игры

Все маршруты раздела требуют access token.

### `GET /api/games/search`

Ищет игры в локальной БД и дополняет выдачу результатами BGG. Поиск в BGG выполняется по названию; дополнительные фильтры применяются к локальной выборке. Локальная выборка включает игры с заполненным BGG ID.

Минимальный запрос:

```json
{
  "name": "Root",
  "offset": 0,
  "limit": 20
}
```

Поля запроса:

| Поле | Тип | Правило |
| --- | --- | --- |
| name | string | Обязательно, непустая строка |
| offset | integer | От 0; при отсутствии используется 0 |
| limit | integer | Обязательно, от 1 до 100 |
| min_play_time_minutes | integer или null | Минимальное время игры |
| max_play_time_minutes | integer или null | Максимальное время игры |
| min_age | integer или null | Возрастной фильтр |
| available_count_players | integer[] | Допустимое количество игроков |
| min_weight | number или null | Нижняя граница сложности |
| max_weight | number или null | Верхняя граница сложности |
| min_polka_rating | number или null | Нижняя граница рейтинга Polka |
| min_bgg_rating | number или null | Нижняя граница рейтинга BGG |
| mechanics | string[] | Названия механик |
| categories | string[] | Названия категорий |
| publishers | string[] | Названия издателей |
| designers | string[] | Имена авторов |

Пример ответа `200 OK` с результатом BGG:

```json
{
  "games": [
    {
      "id": 0,
      "bgg_id": 237182,
      "name": "Root",
      "year_published": 2018
    }
  ],
  "next_offset": 1,
  "has_next": false
}
```

`id` — локальный ID игры; у результата, полученного только из BGG, он равен `0`. `bgg_id` — ID BGG; в текущей локальной выборке это поле не заполняется и возвращается как `0`. `year_published` может отсутствовать.

Для следующей страницы передай `next_offset` как `offset`. `has_next` показывает наличие продолжения. При пустой выдаче `games` — `[]`.

Ошибки: `400` — JSON или поля не прошли привязку и валидацию DTO; `401` — нет авторизации; `500` — ошибка поиска в БД, обращения к BGG или проверки фильтров в сервисе.

### `GET /api/games`

Получает сведения сразу о нескольких играх. В каждом элементе `game_ids` нужно указать ровно один идентификатор: `server_id` или `bgg_id`.

Запрос:

```json
{
  "game_ids": [
    {
      "server_id": 10
    },
    {
      "bgg_id": 237182
    }
  ]
}
```

Список должен содержать хотя бы одну игру. При запросе по `bgg_id` сервер получает сведения из BGG и сохраняет игру локально. В ответе `server_id` уже содержит локальный ID. Порядок элементов ответа соответствует порядку запроса.

Пример элемента ответа `200 OK`:

```json
{
  "games": [
    {
      "server_id": 10,
      "bgg_id": 237182,
      "name": "Root",
      "description": "...",
      "year_published": 2018,
      "bgg_rating": null,
      "polka_rating": null,
      "best_count_players": [],
      "available_count_players": [2, 3, 4],
      "min_play_time_minutes": 60,
      "max_play_time_minutes": 90,
      "min_age": 10,
      "weight": null
    }
  ]
}
```

Неизвестный год возвращается как `0`. Массивы количества игроков могут быть `null`, если соответствующие значения не заполнены.

Ошибки: `400` — неверное тело запроса; `401` — нет авторизации; `500` — ошибка получения или сохранения игры. Пустой список, некорректная комбинация идентификаторов и отсутствие запрошенной игры сейчас также обрабатываются сервисом как `500`.

### `POST /api/games/create`

Создаёт локальную игру без BGG ID.

Запрос:

```json
{
  "name": "My game"
}
```

`name` обязателен и не должен быть пустой строкой.

Ответ `200 OK`:

```json
{
  "game_id": 10,
  "name": "My game"
}
```

Ошибки: `400` — неверное тело; `401` — нет авторизации; `500` — ошибка создания.

## Коллекция

Коллекция определяется по текущему пользователю из access token. В теле запросов передаётся локальный `game_id`.

### `GET /api/collections/`

Тело запроса не требуется. Возвращает игры коллекции, без полей самой записи коллекции: `status`, `note` и `rating`.

Текущий ответ содержит поля игры в PascalCase, поскольку возвращается `model.Game`:

```json
{
  "games": [
    {
      "ID": 10,
      "BggID": 237182,
      "Name": "Root",
      "Description": "...",
      "YearPublished": 2018,
      "BggRating": null,
      "PolkaRating": null,
      "BestCountPlayers": [],
      "AvailableCountPlayers": [2, 3, 4],
      "MinPlayTimeMinutes": 60,
      "MaxPlayTimeMinutes": 90,
      "MinAge": 10,
      "Weight": null,
      "CreatedAt": "2026-11-21T10:00:00Z",
      "UpdatedAt": "2026-11-21T10:00:00Z"
    }
  ]
}
```

Ответ: `200 OK`. Если коллекция пуста — `{"games": []}`. Nullable-поля и незаполненные массивы могут быть `null`.

Ошибки: `401` — нет авторизации; `500` — ошибка получения коллекции.

### `POST /api/collections/add`

Добавляет существующую локальную игру в коллекцию текущего пользователя.

Запрос:

```json
{
  "game_id": 10
}
```

Запись коллекции создаётся с пустым списком статусов. Этот маршрут не принимает настройки `status`, `note` или `rating`.

Ответ `200 OK`:

```json
{
  "message": "success"
}
```

Ошибки: `400` — неверное тело; `401` — нет авторизации; `409` — игра уже есть в коллекции; `500` — ошибка поиска пользователя, игры или сохранения записи.

### `DELETE /api/collections/delete`

Удаляет игру из коллекции текущего пользователя.

Запрос:

```json
{
  "game_id": 10
}
```

Ответ: `200 OK`, без тела.

Ошибки: `400` — неверное тело; `401` — нет авторизации; `500` — ошибка удаления, отсутствие игры или записи в коллекции.

## Сессии

Все маршруты требуют access token. Создатель определяется по токену; `creator_id` из тела запроса не используется.

Читать сессию могут её создатель и зарегистрированные участники. Изменять и удалять сессию может только создатель. ID сессии в пути должен быть положительным целым числом.

Допустимые статусы: `scheduled`, `started`, `finished`, `cancelled`.

### Формат участника

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | integer или null | ID записи участника сессии; передаётся при обновлении существующего участника |
| user_id | integer или null | ID зарегистрированного пользователя |
| name | string или null | Имя гостя, который не является зарегистрированным пользователем |
| score | integer | Очки, значение int32; при отсутствии используется 0 |
| is_winner | boolean | Признак победителя; передавай явно true или false |

Для зарегистрированного участника передай `user_id` и `name: null`. Для гостя передай `user_id: null` и непустое `name` длиной до 255 символов. Должно быть заполнено ровно одно из этих двух полей. Один зарегистрированный пользователь не может повторяться в одной сессии.

`id` участника и `user_id` — разные идентификаторы. У нового участника `id` нужно опустить или передать `null`.

В текущем обработчике `is_winner` используется без значения по умолчанию: не опускай его и не передавай `null`. Неполный объект участника в `PATCH` не объединяется с сохранённым: передавай его актуальные значения целиком.

### `POST /api/sessions`

Минимальный запрос:

```json
{
  "game_id": 10,
  "note": "Вечерняя партия",
  "status": "scheduled"
}
```

Поля запроса:

| Поле | Тип | Правило |
| --- | --- | --- |
| game_id | integer | Обязательно; положительный ID существующей локальной игры |
| note | string или null | До 1024 символов |
| place | string или null | От 1 до 255 символов, если задано; не может состоять из пробелов |
| status | string | Нужен допустимый статус; значение по умолчанию не устанавливается |
| started_at | string или null | Дата начала в RFC3339 |
| finished_at | string или null | Дата завершения в RFC3339 |
| participants | array или null | Массив участников в формате выше |

Если обе даты заданы, начало должно быть строго раньше завершения. Даты нормализуются в UTC с точностью до микросекунд.

Текущее ограничение создания: непустой `participants` приводит к ошибке привязки участников к новой сессии и ответу `500`. Создавай сессию без участников или с `participants: []`, затем задавай состав через `PATCH /api/sessions/:id`. Изменения создания откатываются при ошибке сохранения участника.

Ответ `201 Created`:

```json
{
  "id": 42,
  "game_id": 10,
  "creator_id": 7,
  "note": "Вечерняя партия",
  "place": null,
  "status": "scheduled",
  "started_at": null,
  "finished_at": null,
  "created_at": "2026-11-21T10:00:00Z",
  "updated_at": "2026-11-21T10:00:00Z",
  "participants": []
}
```

### `GET /api/sessions`

Тело запроса не требуется.

Возвращает сессии, где текущий пользователь — создатель или зарегистрированный участник. Порядок: `created_at DESC, id DESC`. Пагинация сейчас не предусмотрена.

Ответ `200 OK`:

```json
{
  "sessions": []
}
```

При наличии сессий каждый элемент имеет формат ответа создания, включая `participants`. Участники загружаются вместе с сессиями и упорядочены по `id ASC`. Пустой состав возвращается как `[]`.

### `GET /api/sessions/:id`

Пример: `GET /api/sessions/42`.

Тело запроса не требуется. Ответ `200 OK` — объект сессии с актуальными участниками в формате ответа создания.

Несуществующая сессия возвращает `404`, отсутствие доступа — `403`.

### `PATCH /api/sessions/:id`

Поддерживает частичное обновление: сервис объединяет переданные данные с текущей записью и проверяет полученное состояние.

Изменение только заметки:

```json
{
  "note": "hello"
}
```

Изменение статуса и даты:

```json
{
  "status": "finished",
  "finished_at": "2026-11-21T12:00:00Z"
}
```

Разрешённые поля: `note`, `place`, `status`, `started_at`, `finished_at`, `participants`. `game_id` через этот маршрут не изменяется.

Правила обновления:

- Непереданные поля сохраняют прежние значения.
- `null` у `note`, `place` и дат также сохраняет прежнее значение. Очистка этих полей в SQL NULL сейчас не поддерживается.
- `note: ""` записывает пустую строку.
- Пустой `place` или строка из пробелов отклоняется с `400`.
- Отсутствующий, `null` или пустой `status` сохраняет прежний статус.
- Даты проверяются с учётом сохранённых значений другой даты.
- `id`, `creator_id`, `created_at` и `updated_at` задаются сервером.
- Пустой объект `{}` не отклоняется; успешное сохранение обновляет `updated_at`.

Правила для `participants`:

| Значение | Действие |
| --- | --- |
| Поле отсутствует | Состав не меняется |
| null | Состав не меняется |
| [] | Все участники удаляются |
| Непустой массив | Становится полным новым составом сессии |

Пример замены состава:

```json
{
  "participants": [
    {
      "id": 15,
      "user_id": 7,
      "name": null,
      "score": 12,
      "is_winner": true
    },
    {
      "user_id": null,
      "name": "Гость",
      "score": 8,
      "is_winner": false
    }
  ]
}
```

В этом примере запись участника `15` должна уже принадлежать данной сессии. Она обновится, гость будет создан, а прежние участники, отсутствующие в массиве, удалятся. Для сохранения прежних участников включай их в новый список с их `id`.

Сессия и состав участников сохраняются в одной транзакции. При ошибке все изменения откатываются. Неверные или повторяющиеся ID участников и другие ошибки состава сейчас могут возвращаться как `500`.

Ответ `200 OK` — сохранённая сессия с новым `updated_at`, актуальным составом и созданными ID участников.

Если между чтением и сохранением сессия изменилась другим запросом, сервер возвращает `409`. Клиентское поле `updated_at` в DTO запроса не предусмотрено.

### `DELETE /api/sessions/:id`

Пример: `DELETE /api/sessions/42`.

Тело запроса не требуется. Удаляет сессию, её участников и связи изображений согласно каскадным ограничениям БД.

Ответ: `204 No Content`, без тела.

### Ошибки маршрутов сессий

| Код | Причина | Пример error |
| --- | --- | --- |
| 400 | Некорректный ID в пути | invalid session id |
| 400 | Неверный JSON или формат даты | invalid request body |
| 400 | Нарушены ограничения полей сессии | invalid session |
| 401 | Нет или невалиден access token | unauthorized |
| 403 | Нет прав на чтение или изменение | session access forbidden |
| 404 | Сессия не найдена | session not found |
| 404 | Игра не найдена | game not found |
| 409 | Конфликт сохранения | session data conflict |
| 500 | Ошибка БД или обработки участников | internal server error |

## Формат ошибок

Большинство обработчиков возвращают JSON с полем `error`:

```json
{
  "error": "invalid session"
}
```

Для `/games/*` ошибки сервисного слоя сейчас передаются в `error` как объект Go, поэтому сообщение может выглядеть как `{"error": {}}`. Подробная причина таких ошибок записывается в лог сервера.
